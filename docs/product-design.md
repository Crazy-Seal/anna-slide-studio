## 1. 定位

**一句话：把「开会前 30 分钟做 PPT」压缩成「5 分钟拿到一份能继续改的文件」。**

市面上 AI 做 PPT 的产品，大多卡在同一个地方：**给你一堆好看的图，但你没法改**。导出的要么是图片、要么是 PDF、要么只能在它自己的编辑器里打开。要真拿去开会，还得重做一遍。

我们的差异只有一条，但足够硬：

> **产出真正的 .pptx —— PowerPoint 和 WPS 都能打开，每个字都能继续编辑。**

### 为什么这条是差异点

| 方案 | 用户拿到什么 | 能改吗 | 能拿去开会吗 |
|---|---|---|---|
| 生成图片/长图 | PNG | ❌ | ❌ 投影糊、改不了 |
| 生成 PDF | PDF | ❌ | 😐 不能改 |
| 在线编辑器（Gamma 类） | 只能在他家编辑器改 | 😐 要登录、要付费 | 😐 得导出 |
| **我们** | **.pptx** | ✅ 原生可编辑 | ✅ |

这条差异也决定了技术路线：必须在浏览器里生成 OOXML，而不是截图拼贴。

## 2. 目标用户与场景

不做"所有人"，只服务一类人：**临时要交差的人**。

| 场景 | 是谁 | 痛点 | 他要的 |
|---|---|---|---|
| **S1 周会/季度会** | 产品、运营 | 有内容没结构，排版耗时间 | 快速出一版能讲的骨架，自己再填细节 |
| **S2 临时汇报** | 被通知"明天讲一下"的人 | 完全没头绪 | 从零到一份完整稿，能直接用 |
| **S3 甲方/客户提案** | 乙方、自由职业者 | 要专业感，但请不起设计 | 看起来不像 Word 转化出来的 |

**共同点**：都有明确的"交付时间"，都要**交出一个文件**，而不是"在某个网页里看看"。

**不是我们的用户**：需要精细设计控制的专业设计师（他们用 Keynote/Figma）；需要复杂图表的数据分析师（他们用 Excel 出图）。

## 3. 产品原则

四条，用来砍需求：

1. **先确认方向，再花力气**
   用户最贵的成本不是"某页写得不好"，是"整份做完发现结构不对"。所以大纲必须可改、必须先确认。

2. **宁可少一点，不可不可用**
   7 种版式做到不出错，胜过大而全但经常溢出、错位、字体乱。

3. **确定性交给代码，创造力交给模型**
   模型只管"写什么"，不管"放哪、多大、会不会溢出"。排版永远是代码算的。

4. **额度是用户的钱**
   每一次模型调用都要让用户看得见、猜得到、能拒绝。不做静默调用、不做自动重试超过一次。

## 4. 核心流程

三步，任何一步都能退回去改：

```
① 说需求 ──→ ② 审大纲 ──→ ③ 拿文件
   ↓            ↓            ↓
 10 秒        30 秒        2 分钟
```

### 状态机

```
[idle] ──输入──> [outlining] ──成功──> [outline_ready]
                      │                      │
                      └──失败──> [error]     ├──编辑大纲──> [outline_ready]
                                             ├──确认──> [generating] ──> [deck_ready]
                                             └──重来──> [idle]
                                                          │
                                          [deck_ready] <──┤
                                             ├──改字/换版式/换主题（本地，不花钱）
                                             ├──重写某页（1 次调用）
                                             └──导出 ──> [exporting] ──> 完成
```

## 5. 界面规格

窗口默认 1100×720，最小 380×420。布局分三态。

### 5.1 输入态

```
┌──────────────────────────────────────────────┐
│  幻灯片工坊                        剩余 998 ▾ │
├──────────────────────────────────────────────┤
│                                              │
│   要做一份什么 PPT？                          │
│   ┌────────────────────────────────────────┐ │
│   │ 给产品团队做一次季度回顾，讲清成绩、     │ │
│   │ 问题和下季度计划                        │ │
│   └────────────────────────────────────────┘ │
│                                              │
│   受众  [管理层] [团队] [客户] [通用]         │
│   页数  [ 6 ] [ 8 ] [10] [12]                 │
│   风格  [克制] [简洁] [有力] [技术]           │
│                                              │
│   试试： 季度复盘 · 项目立项 · 产品介绍        │
│                                              │
│                          [ 生成大纲  →  ]     │
│                    预计 1 次调用 · 约 3 秒     │
└──────────────────────────────────────────────┘
```

要点：
- **主输入框是唯一视觉焦点**，其余是可选修饰
- 三个选择器都有默认值，用户什么都不选也能生成
- 底部**明确写"1 次调用"**——从第一次交互就建立额度透明
- 示例 chips 降低冷启动门槛

### 5.2 大纲态

```
┌──────────────────────────────────────────────┐
│  ← 重来       大纲 · 8 页        剩余 998 ▾  │
├──────────────────────────────────────────────┤
│  1  ⠿  季度概览                    [✎] [🗑]  │
│  2  ⠿  三个关键指标                [✎] [🗑]  │
│  3  ⠿  我们做对了什么              [✎] [🗑]  │
│  4  ⠿  还没解决的问题        ⚠ 内容偏泛  [✎]  │
│  5  ⠿  下季度优先级                [✎] [🗑]  │
│  + 添加一页                                   │
├──────────────────────────────────────────────┤
│  提示：结构比文字重要，这步不花钱              │
│                    [ 生成正文  →  ]           │
│                    预计 1 次调用               │
└──────────────────────────────────────────────┘
```

要点：
- **行内编辑**，点了直接改，不弹窗
- 拖拽排序（⠿ 手柄）
- 质量提示（⚠）用**规则**判断（标题过短、重复、空泛词），不调模型
- 底部一句话点明"这步不花钱"，鼓励用户多改

### 5.3 画布态

```
┌───────────────────────────────────────────────────────────┐
│  ← 大纲   主题 ▾    [重写本页]        [导出 .pptx]  998 ▾ │
├────────┬──────────────────────────────────────────────────┤
│ ▢ 1    │                                                  │
│ ▢ 2    │        ┌────────────────────────────┐            │
│ ▣ 3    │        │                            │            │
│ ▢ 4    │        │   三个关键指标              │            │
│ ▢ 5    │        │   +38%   4.2   -12%        │            │
│ ▢ 6    │        │                            │            │
│        │        └────────────────────────────┘            │
│        │        第 2 / 8 页 · 版式 [指标 ▾]                │
└────────┴──────────────────────────────────────────────────┘
```

要点：
- 左缩略图 132px 宽，可滚动
- 中间画布等比缩放（基准 1280×720），窗口变小时整体缩，不重排
- **就地编辑**：点文字直接改（`contenteditable`），失焦即生效，不花钱
- 版式可手动切换（同一个内容换一种排法）
- 导出按钮常驻右上，额度常驻右下

## 6. 版式系统

7 种，覆盖 90% 的汇报场景。每种都是**固定几何**，不是自由布局——这是"不出错"的保证。

| 版式 | 用在哪 | 视觉结构 | 内容上限 |
|---|---|---|---|
| `title` | 封面 | 大标题居中偏左 + 细横线 + 副标题 | 标题 40 字 |
| `agenda` | 目录 | 编号列表，两列 | 6 条 |
| `bullets` | 要点 | 标题 + 左对齐要点，每条前有短横 | 5 条 × 28 字 |
| `two_col` | 对比 | 标题 + 左右双栏，各有小标题 | 2 列 × 4 条 |
| `metrics` | 数字 | 标题 + 2~4 个巨号数字并排 | 4 项 |
| `quote` | 引用 | 大号引文居中 + 出处 | 60 字 |
| `closing` | 结尾 | 大标题 + 副标题，留白多 | 20 字 |

**为什么会自动不溢出**：每种版式的字号、行高、换行宽度都是写死的；文字超限时先降字号（最低到下限），仍超则截断加省略号。**模型永远不需要"注意别写太长"**——它写长了也不会崩。

## 7. 主题系统

4 套，只改颜色和字重，不改布局。全部用 CSS 变量实现。

| 主题 | 气质 | 底色 | 主色 | 文字 | 用在 |
|---|---|---|---|---|---|
| `editorial` | 克制、纸感 | `#FAF9F7` | `#1A1A1A` | `#1A1A1A` | 汇报、复盘（默认） |
| `minimal` | 干净、留白 | `#FFFFFF` | `#2563EB` | `#111827` | 产品介绍、提案 |
| `bold` | 有力、强对比 | `#0F0F0F` | `#F5F5F5` | `#FFFFFF` | 发布、路演 |
| `tech` | 冷色、精密 | `#0B1220` | `#38BDF8` | `#E2E8F0` | 技术方案 |

### 字体约束（重要）

平台 CSP 是 `font-src 'self' data:`，**不能加载 Google Fonts 或任何外链字体**。全部使用系统字体栈：

```css
font-family: "PingFang SC", "Microsoft YaHei", "Source Han Sans SC",
             "Noto Sans CJK SC", -apple-system, sans-serif;
```

这既是约束也是好事——中文系统字体在目标用户机器上一定存在，渲染零等待，也不用担心字体加载失败导致版式跳变。

## 8. 文案规范

### 8.1 语气

像一个靠谱的同事，不像一个 AI。**不卖萌、不邀功、不解释自己有多厉害。**

| 场合 | 不要写 | 要写 |
|---|---|---|
| 生成中 | "AI 正在施展魔法✨" | "正在构思结构…" |
| 空态 | "还没有内容哦～" | "输入一句话，开始生成" |
| 成功 | "太棒了！已为您生成！" | "8 页，可以导出" |
| 额度不足 | "额度已耗尽" | "额度不足，无法生成。可联系平台补充" |

### 8.2 关键文案

| 位置 | 文案 |
|---|---|
| 主按钮 | 生成大纲 → / 生成正文 → / 导出 .pptx |
| 额度提示 | 剩余 {n} · 本次约消耗 {m} |
| 大纲页提示 | 结构比文字重要，这步不花钱 |
| 导出中 | 正在打包… |
| 导出成功 | 已保存 {filename} |
| 截断警告 | 内容偏长，已精简为 {n} 条 |
| JSON 修复中 | 格式有点问题，正在修复… |

### 8.3 错误文案

必须**说清发生了什么 + 下一步能做什么**，不暴露技术细节：

| 情况 | 文案 |
|---|---|
| 模型输出无法解析 | 生成的内容格式不对，已自动重试一次仍失败。请换个说法再试。 |
| 额度不足 | 额度不足，无法生成。可联系平台补充额度。 |
| 网络/宿主超时 | 生成超时了，请稍后重试。本次未扣额度。 |
| 导出失败 | 文件打包失败，请重试。若持续失败，可先截图保存预览。 |
| 本地未接模型 | 当前是本地预览模式，未连接模型。 |

## 9. 交互细节

| 交互 | 行为 | 为什么 |
|---|---|---|
| 输入框 `Ctrl+Enter` | 生成大纲 | 少一次鼠标移动 |
| 大纲行 `Enter` | 保存并新建下一行 | 连续编辑不中断 |
| 画布点文字 | 进入编辑 | 所见即所得，无弹窗 |
| 编辑失焦 | 立即生效（本地） | 不等"保存"按钮 |
| 缩略图点击 | 跳该页 | 快速定位 |
| `←` `→` | 上一页/下一页 | 预览时手不离开键盘 |
| 换主题 | 立即重绘，不重新生成 | 纯本地，零成本 |
| 换版式 | 立即重排，内容不变 | 让用户觉得"便宜" |
| 重写本页 | 只重生成当前页（1 次调用） | 精准迭代，不整份重来 |

### 加载态设计

**不显示假进度条。** 三个阶段用文案区分，因为真实耗时不可预测：

```
"正在构思结构…"   （大纲，约 3 秒）
"正在写第 3 / 8 页…"  （正文分批时才有，真进度）
"正在打包文件…"   （导出）
```

## 11. Demo 剧本（评审 3 分钟）

这条路径要保证**每一步都成功**，因为它就是评审的体验路径：

1. 商店点开 → 输入「给产品团队做一次季度回顾，8 页」→ 生成
2. 大纲出来 → **当场改一个标题、删一页、调一次顺序**（证明可编辑）
3. 生成正文 → 画布出现
4. **点一处文字改成自己的话**（证明所见即所得）
5. 换一次主题（证明零成本）
6. 导出 → 打开 pptx → **在 PowerPoint 里改一个字**（证明真文件）

第 6 步是整个 demo 的高潮，必须万无一失。

## 12. 成功标准

| 指标 | 目标 |
|---|---|
| 从输入到拿到文件 | ≤ 90 秒（含用户改大纲的时间） |
| 模型调用次数 | 2 次（重写单页 +1） |
| 生成失败率（mock 与真实各测 20 次） | < 5%（含修复重试后） |
| 导出成功率 | 100%（PowerPoint + WPS 双验） |
| 版式溢出 | 0（任何合法内容都不溢出） |
| 冷启动到可交互 | < 1 秒（无外链资源） |

## 13. 明确不做

写下来是为了防止范围膨胀：

- ❌ AI 配图 / 图库（12–42 CU/张，会烧穿额度）
- ❌ 联网调研、引用来源
- ❌ 导入 .docx / .md / PDF
- ❌ 自定义模板 / 上传品牌色
- ❌ 多人协作、分享链接、云端历史
- ❌ 动画、切换效果、演讲者视图
- ❌ 图表（柱状/折线）——v1 只有"大数字"，真图表留 v2
- ❌ 移动端适配（v1 只声明 `desktop`）
- ❌ 中英双语界面（v1 只中文）
